## Состояние документации

Уже описаны:
- общий обзор компонентов и потоки сканирования;
- отдельные уровни тестирования счётчика и обнаружения карточек на полном скриншоте;
- формат и правила добавления размеченных screenshot fixtures;
- известное ограничение проверки меток `unowned` и текущее отсутствие размеченных полных скриншотов;
- локальный запуск, CI и базовые регрессионные сценарии;
- журнал заметных улучшений и проверок разработки;
- основные административные операции с эталонными тестами счётчика и их влияние на Git-фикстуры.

Подробные контракты API и бизнес-правил ещё требуют отдельной полной инвентаризации. Приоритетные пробелы:

1. Полный список API: входные/выходные модели, статусы ошибок и авторизация по каждому маршруту.
2. Инвентарь и список «Ищу»: транзакционные границы, повторное сканирование и согласованность состояний.
3. Обмены: переходы состояний, согласия участников, передача кода и завершение обмена.
4. Мониторинг и устранение неполадок; маршрут Render → Sentry → GitHub source mapping ещё не подтверждён end-to-end.

## Правило актуальности

При изменении API, схемы БД, алгоритма сканирования или пользовательского сценария обновляйте соответствующий документ в том же PR. Если поведение ещё не проверено или в коде обнаружено противоречие, явно помечайте это как «требует проверки», а не описывайте как гарантированное.
