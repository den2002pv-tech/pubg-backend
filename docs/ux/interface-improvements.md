# UX proposal: PUBG Card Exchange — интерфейс следующего этапа

**Статус:** предложение к реализации, не изменяет production UI.  
**Базовая ветка:** `feature/card-counter`  
**Рабочая ветка:** `ux/interface-improvements`  
**Основание:** просмотр `index.html` в `feature/card-counter`, существующий UX-аудит в Linear и каталог компонентов Lumen UI. Это проектное предложение; гипотезы нужно проверить на реальных пользователях.

## Цель

Сделать три главных сценария понятнее с телефона: быстро найти карту, без ошибок обновить коллекцию, проверить результат сканирования и подготовить обмен. Не переписывать уже работающие фильтры, доступные вкладки и очередь повторного сохранения без необходимости.

## Что уже есть и не нужно дублировать

В текущем интерфейсе уже присутствуют тёмная тема, вкладки «Сканер» и «Инвентарь», статистические быстрые фильтры, чипы, поиск и сортировка, сетка карточек, управление количеством, статус сохранения, отдельные пустые состояния и сравнение скана с эталоном. В предыдущем UX-аудите также отмечены доступные вкладки, обработка ошибок сохранения и подсказки сканера. Следующий этап должен улучшать иерархию и путь пользователя, а не просто добавлять ещё элементы управления.

## Рекомендуемая концепция

### 1. Верхняя зона: один ясный заголовок и полезный итог

- Заменить повторяющийся заголовок и подзаголовок на компактную шапку: **«Моя коллекция»**, число собранных карт и короткий прогресс.
- Показывать статус подключения/синхронизации рядом с профилем, а не как отдельный конкурирующий блок.
- Оставить одну главную кнопку на экран: в инвентаре — «Сканировать скриншот», в сканере — «Выбрать скриншот» или «Проверить результаты».
- Не показывать крупные KPI, если они не помогают принять решение. Статистику «Есть / Дубликаты / Ищу» оставить быстрыми фильтрами, явно показывая, что нажатие меняет список.

### 2. Мобильная навигация

- На телефоне закрепить внизу компактную навигацию из двух основных пунктов: **Сканер** и **Коллекция**; учитывать безопасную область Telegram WebApp.
- Текущую семантику вкладок и клавиатурную навигацию сохранить. Не превращать переключатели в декоративные кнопки без ARIA-состояния.
- На широком экране оставить верхние вкладки/панели; не добавлять полноценный сайдбар только ради двух основных разделов.
- Проверить, что фиксированная навигация не перекрывает последнюю строку карточек, диалоги и клавиатуру телефона.

### 3. Инвентарь: сначала цель, потом фильтры

Рекомендуемая последовательность сверху вниз:

1. Заголовок + компактный прогресс коллекции.
2. Большой поиск по названию/ID.
3. Короткая строка быстрых фильтров: **Все**, **Не хватает**, **Дубликаты**, **Ищу**.
4. Кнопка «Фильтры» для редких условий (редкость, сортировка и другие уже существующие параметры), открывающая компактную панель.
5. Строка результата: «Показано 24 из 120 карт» и явная команда «Сбросить», когда фильтры активны.
6. Сетка карточек.

Важные детали:
- Не дублировать одни и те же фильтры одновременно в KPI, чипах и дополнительной панели. Выбрать один основной уровень, а статистические значения встроить в чипы.
- Активные фильтры показывать как снимаемые чипы; сброс фильтров не должен неожиданно очищать поисковую строку, если пользователь сбрасывает только один фильтр.
- Запоминать последнюю сортировку и вид списка в пределах сессии, если это не ломает предсказуемость.
- На экране с активным поиском показывать кнопку очистки; при нулевом результате предлагать очистить запрос, а не только сообщать «Ничего не найдено».

### 4. Карточка: меньше визуального шума

- Сохранить изображение главным элементом; не уменьшать его ради второстепенных меток.
- На изображении оставить только количество и одну кнопку «Ищу». Редкость и число дубликатов показать ниже компактными текстовыми метками.
- Сделать название более читаемым и выровнять высоту карточек. Полное название и дополнительные сведения доступны по нажатию на карточку.
- Управление количеством оставить с крупными кнопками **− / количество / +**; обеспечить понятные доступные имена, например «Уменьшить количество карты …».
- Когда количество становится 0, показывать ясное состояние «Нет в коллекции». Не использовать только изменение цвета как сигнал.
- Не открывать подробности при нажатии на плюс/минус или звезду; интерактивные зоны должны быть независимыми.
- Проверить сетку на ширине 320–430 px: изображение должно оставаться различимым, текст не обрезаться критически, кнопки — не слипаться.

### 5. Сканер: пошаговый сценарий вместо одной большой формы

Предлагаемая структура:
1. **Выберите скриншот** — видимая зона загрузки, краткая подсказка о поддерживаемом скриншоте и состояние загрузки.
2. **Проверьте распознавание** — количество найденных карт, сколько совпало с каталогом, сколько требуют проверки.
3. **Подтвердите изменения** — список обнаруженных карт с количеством на скриншоте, текущим количеством в коллекции и понятным результатом изменения.
4. **Сохраните** — отдельная кнопка подтверждения и результат «Сохранено» либо «Не удалось сохранить — Повторить».

Дополнительно:
- Не считать любое найденное изображение достоверным совпадением. Для сомнительных/неизвестных карт показать текст «Нужно проверить» и действие «Сравнить с эталоном».
- В каждой строке результата дать быстро изменить распознанное количество до сохранения.
- Сравнение кропа и эталона оставить, но открывать его по явному действию; в диалоге показывать названия «На скриншоте» и «Эталон», доступное закрытие и возврат фокуса.
- При долгой обработке показывать этап («Загружаем», «Ищем карты», «Сопоставляем», «Готовим сохранение»), но не имитировать проценты, если backend их не предоставляет.
- После успешного сохранения показать краткий итог: сколько карт обновлено и сколько требуют ручной проверки.

### 6. Обмен и список «Ищу»

- В разделе «Ищу» показывать сначала недостающие карты, а затем — доступные предложения обмена; не смешивать инвентарь и входящие/исходящие заявки в одном неразличимом списке.
- В карточке предложения выделить главное: «Отдам» и «Получу», имя игрока и доступное действие.
- Для заявок добавить ясные статусы с текстом: «Ожидает ответа», «Принята», «Код получен», «Завершена», «Отменена». Цвет может дополнять, но не заменять текст.
- Перед необратимыми действиями показать точное последствие; после действия — подтверждение и актуальный статус.
- Когда карта добавляется в коллекцию в положительном количестве, убедиться, что она удаляется из «Ищу» согласно текущему правилу бизнес-логики.

### 7. Визуальная система

- Сохранить тёмную игровую атмосферу, но уменьшить количество конкурирующих обводок, свечений и градиентов. Акцентный синий — основное действие, золотой — «Ищу»/редкость, зелёный — подтверждённый успех, красный — ошибка или разрушительное действие.
- Использовать 8-пиксельный базовый шаг для отступов; один радиус для обычных контролов и один для крупных поверхностей.
- Основной текст — не менее 14 px для типового мобильного контента; вторичные подписи — желательно от 12 px, с достаточным контрастом. Критичные значения количества не должны быть мелкими.
- Цель нажатия — около 44×44 px там, где возможно. Сохранять масштабирование браузера и видимый фокус.
- Добавить светлую тему только после проверки контрастов и реального спроса; сейчас лучше качественно довести одну тему, чем поддерживать две непоследовательно.
- Не вводить FLOWSTACK как новую зависимость без подтверждения, что пакет уже установлен и совместим с приложением. Lumen можно использовать как контракт для Tabs, Card, Empty и Grid; в текущем проекте перед внедрением нужно сверить реальные зависимости и не смешивать две системы компонентов без плана миграции.

## Приоритеты реализации

| Приоритет | Работа | Почему | Критерий готовности |
|---|---|---|---|
| P0 | Упростить верхнюю иерархию инвентаря и свести быстрые фильтры к одному уровню | Меньше визуальной конкуренции | Пользователь понимает активный фильтр и число результатов без подсказки |
| P0 | Разделить шаги сканирования и подтверждения | Меньше риск случайно принять ошибочное распознавание | Можно проверить количество до сохранения; неизвестные карты видны отдельно |
| P0 | Уточнить обратную связь после сохранения | Доверие к данным коллекции | Успех и ошибка визуально различаются, при ошибке доступен повтор |
| P1 | Упростить карточку и детали по нажатию | Больше полезной площади на телефоне | Название, изображение и количество читаемы на 320 px |
| P1 | Сделать мобильную навигацию удобнее одной рукой | Быстрее переход между основными задачами | Нижняя навигация не перекрывает контент и безопасные области |
| P1 | Явные статусы обмена и заявок | Снижение ошибок в обмене | Статус понятен без цвета и без открытия деталей |
| P2 | Полировка темы и motion | Более целостный интерфейс | Проверены контраст, reduced motion и оба размера экрана |

## План проверки

### Размеры и устройства
- Ширины: 320, 360, 390, 430 и 768/1280 px.
- Telegram WebApp на Android: нижняя панель, безопасные области, открытие клавиатуры, возврат из просмотра изображения.
- Браузер вне Telegram: понятный экран запуска/объяснение ограничения авторизации.

### Сценарии
- Найти карту по полному и частичному названию; очистить поиск.
- Активировать «Не хватает», затем поиск; снять только один фильтр.
- Изменить количество с 0 → 1 и 1 → 0; проверить удаление из «Ищу».
- Загрузить скриншот, проверить неоднозначную карту, поправить количество, подтвердить.
- Проверить повторное сканирование одного изображения: не должно появляться двойных записей или неверного накопления количества.
- Имитировать ошибку сети при сохранении и повторить операцию.
- Открыть сравнение кропа и эталона, закрыть крестиком и Escape (если доступно), проверить возврат фокуса.
- Проверить массовые действия, отмену и подтверждение.
- Пройти основные сценарии только клавиатурой и с экранным диктором.

### Метрики успеха
- Время от открытия приложения до нахождения карты.
- Доля успешного завершения сканирования без помощи.
- Число исправлений количества после распознавания.
- Доля сохранений, завершённых без повторной попытки.
- Ошибки при изменении количества и состояния «Ищу».

Не задавать произвольные целевые проценты до получения базовых значений; сначала снять baseline, затем сравнить после изменений.

## Что делать дальше

1. Сначала реализовать P0 небольшими изменениями в существующем `index.html`, не переписывая весь экран.
2. Добавить/обновить регрессионные UI-тесты на фильтры, сохранение, нулевые состояния и подтверждение сканирования.
3. Проверить реальные зависимости и решить, какие Lumen-компоненты можно использовать без миграции.
4. Сделать preview-деплой и пройти ручной сценарий в Telegram WebApp.
5. Только после проверки объединять изменения с `feature/card-counter`; эта ветка содержит только предложение и не меняет рабочий интерфейс.
