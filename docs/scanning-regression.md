# Регрессионное тестирование сканирования скриншотов

## Цель

Проверить весь путь от исходного скриншота до списка обнаруженных карточек и распознанного количества. Тесты счётчика на отдельных кропах не проверяют, правильно ли сканер нашёл прямоугольники карточек на полном изображении.

Этот документ сверён с `scanner.py`, `tests/test_screenshot_fixtures.py` и манифестом `tests/fixtures/screenshots/cases.json` в ветке `feature/card-counter`.

## Уровни тестирования

### Уровень A — счётчик на кропе

Источник данных: `tests/fixtures/counter/cases.json` и `tests/fixtures/counter/images/`.

Проверяется распознавание количества на готовом изображении одной карточки. Этот набор помогает находить ошибки в цифрах, знаке умножения, выборе области счётчика и обработке отсутствующего счётчика. Он не доказывает корректность обнаружения карточек на исходном скриншоте.

### Уровень B — полный скриншот

Источник данных:
- `tests/fixtures/screenshots/cases.json`;
- оригинальные скриншоты, указанные в `image_path`;
- `tests/test_screenshot_fixtures.py`.

Тест вызывает `scan_screenshot(image, save_previews=False)`, а затем проверяет число результатов, геометрию прямоугольников и количество каждой сопоставленной карточки.

Для каждой размеченной карточки поле `box` содержит `[x, y, width, height]` в координатах исходного скриншота. Не размечайте координаты по уменьшенному превью или отдельному кропу.

Сходство прямоугольников оценивается Intersection over Union (IoU). Текущий порог в тесте — `0.70`. Для сопоставления ожидаемых и найденных областей используется жадный выбор наилучшего IoU среди ещё не сопоставленных результатов.

## Формат манифеста

Пример одной записи:

```json
{
  "version": 1,
  "cases": [
    {
      "id": "inventory-gray-cards-01",
      "image_path": "tests/fixtures/screenshots/images/inventory-gray-cards-01.png",
      "cards": [
        {
          "card_id": "verified-catalog-id",
          "card_name": "Проверенное название",
          "box": [198, 147, 228, 337],
          "expected_quantity": 10,
          "state": "owned"
        }
      ]
    }
  ]
}
```

Правила:
- `id` — стабильный, уникальный идентификатор случая.
- `image_path` — относительный путь от корня репозитория. Абсолютные пути и сегменты `..` запрещены тестом.
- `cards` — вручную проверенные области карточек на полном скриншоте.
- `box` — целочисленные координаты `[x, y, width, height]` исходного изображения.
- `expected_quantity` — вручную проверенное положительное целое число для принадлежащей инвентарю карты. Если на карте нет счётчика, обычно ожидается `1`.
- `card_id` и `card_name` полезны для диагностики; фактическая проверка в текущем тесте использует геометрию и количество.
- `state` может быть `owned` или `unowned`. Если поле отсутствует, тест считает состояние `owned`.

Сохраняйте оригинальные размеры и пиксели скриншота. Не меняйте эталонную рамку или количество только для получения зелёного теста.

## Добавление нового случая

1. Выберите оригинальный скриншот и убедитесь, что его можно хранить в репозитории без приватных данных.
2. Откройте изображение в исходном разрешении и вручную разметьте каждую интересующую область карточки.
3. Запишите координаты `[x, y, width, height]` относительно исходного изображения.
4. Проверьте количество каждой принадлежащей инвентарю карты по изображению, а не по ответу алгоритма.
5. Добавьте запись в `cases.json` и положите оригинальное изображение в `tests/fixtures/screenshots/images/`.
6. Запустите `python -m pytest -q tests/test_screenshot_fixtures.py`.
7. Если тест упал, изучите прямоугольники и `counter_debug` в сообщении ошибки. Исправляйте алгоритм или исправляйте разметку только после независимой проверки эталона.
8. Просмотрите diff и убедитесь, что изображение, манифест и код соответствуют одному тестовому случаю.

## Обязательные классы примеров

Постепенно наполняйте набор вручную проверенными примерами:

- обычные карты и несколько рядов/столбцов;
- серые карты низкой редкости и карты с низкой насыщенностью;
- затемнённые или недоступные карты на экранах, где они визуально похожи на карты инвентаря;
- отсутствие счётчика и количество из одной или двух цифр;
- разные разрешения, масштабирование, плотность карточек и частично обрезанные элементы интерфейса;
- скриншоты с фоновыми панелями, яркими декоративными областями и другими объектами, похожими на контуры карт.

Не добавляйте только удобные изображения: сложные примеры нужны именно для обнаружения ложноположительных и пропущенных областей.

## Важное ограничение текущего теста: владение картой

В `scanner.py` функция `scan_screenshot` вызывает геометрическое обнаружение, затем распознаёт счётчик и считает хэши. Она не определяет владение картой на основании отдельного поля `state` из манифеста.

В `tests/test_screenshot_fixtures.py` список `expected_unowned` сейчас формируется, но не используется для отдельной проверки каждой размеченной незачтённой области. Тест сравнивает число найденных результатов с числом карточек, размеченных как `owned`, и проверяет геометрию/количество этих принадлежащих карт. Поэтому метка `unowned` сама по себе не подтверждает, что затемнённая карта корректно классифицируется как недоступная; она лишь влияет на ожидаемое общее количество.

Пока отдельная логика классификации владения и её тесты не реализованы, не описывайте это покрытие как гарантированное. Для проверки именно этого поведения требуется дополнительный тест-контракт: для каждой размеченной `unowned` области проверять, что она не попала в сохранённый инвентарь, при этом не отбрасывать принадлежащие пользователю серые карты. Это отдельная задача от обнаружения геометрии и распознавания счётчика.

## Текущее состояние набора

На момент сверки манифест `tests/fixtures/screenshots/cases.json` содержит `"cases": []`. Это означает, что тесты полного скриншота пропускают проверки размеченных случаев. Зелёный общий запуск в таком состоянии не является доказательством точности обнаружения контуров.

Проверьте содержимое манифеста перед тем, как считать покрытие достаточным.

## Команды

```sh
# Счётчик на отдельных кропах
python -m pytest -q tests/test_counter_fixtures.py

# Обнаружение областей и количества на полном скриншоте
python -m pytest -q tests/test_screenshot_fixtures.py

# Весь каталог тестов
python -m pytest -v tests

# Полный набор, как в основном CI
python -m pytest -q
```

Реальные результаты запуска записывайте отдельно. Документация не заменяет запуск тестов на текущем коммите.
