# Развёртывание PUBG Cards

## Текущая схема

- Backend и frontend работают на Enzonic. Публичный origin: `https://pubg-card.enzonic.dev`.
- FastAPI обслуживает frontend по `/`, админ-панель по `/admin`, API и `GET /health` на том же origin. Поэтому `API = ''` в `index.html` и `API_BASE = ''` в `admin.html` используют same-origin API и не требуют CORS.
- PostgreSQL остаётся на Render. Приложение получает DSN только из `DATABASE_URL`; не меняйте его при деплое backend.
- Публичные ссылки на ресурсы приложения формируются из `PUBLIC_BASE_URL`; безопасное значение по умолчанию — `https://pubg-card.enzonic.dev`.

В репозитории нет конфигурационного файла Enzonic, поэтому фактические build/start команды, привязку порта и кеширование платформы нельзя подтвердить по Git. Ожидаемая команда запуска приложения — `python3 -m uvicorn main:app`; проверьте в панели Enzonic, что настройка запуска соответствует требованиям платформы по адресу прослушивания и порту. Зависимости проекта перечислены в `requirements.txt`. Установка пакетов при каждом старте не настроена этим репозиторием; настройку build/cache можно подтвердить только в Enzonic.

Для ограничения ресурсов сканирования доступны `SCAN_CONCURRENCY` (максимум одновременных сканов, по умолчанию `1`), `CV2_NUM_THREADS` (потоки OpenCV, по умолчанию `1`), `SCAN_RATE_LIMIT` (запросов на один ключ за период, по умолчанию `10`) и `SCAN_RATE_WINDOW_SECONDS` (период в секундах, по умолчанию `60`). `POST /scan` ограничивает анонимных по адресу клиента и авторизованных по проверенному Telegram user ID. Загрузка ограничена 15 МБ и 30 мегапикселями.

## Переменные окружения

Храните значения только в настройках окружения сервиса, не в Git и не в логах. В частности, необходимы `DATABASE_URL` и (для Telegram-функций) `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`; админ-функциям требуются `ADMIN_PASSWORD` и рекомендуется `ADMIN_SESSION_SECRET`. `PUBLIC_BASE_URL` можно задать явно, если публичный origin меняется. Для отображения версии приложение читает опциональную переменную `APP_COMMIT`; наличие автоматически предоставляемой Enzonic переменной идентификатора коммита не подтверждено.

## Telegram

Код принимает webhook на `POST /telegram/webhook`, сверяет `X-Telegram-Bot-Api-Secret-Token` с `TELEGRAM_WEBHOOK_SECRET` и использует `TELEGRAM_BOT_TOKEN` для вызовов Bot API. Кнопка Telegram Mini App открывает `PUBLIC_BASE_URL`. Наличие маршрута в исходном коде не подтверждает регистрацию webhook в Telegram — проверяйте её отдельно в безопасном канале, не публикуя URL с секретом.

## Проверка после изменения

1. Проверьте ветку, SHA коммита и состав diff.
2. Убедитесь, что Enzonic собрал и запустил нужный SHA; настройки сервиса в панели не подтверждаются этим репозиторием.
3. Проверьте `GET /health` и пользовательские сценарии. Health endpoint подтверждает доступность HTTP-процесса, но не исправность операций с БД, авторизации, сканирования или обменов.
4. Проверьте same-origin frontend/API, ссылки изображений и Telegram Mini App.
5. Убедитесь, что PostgreSQL доступен через заданный `DATABASE_URL`; не запускайте destructive SQL для проверки деплоя.
6. Проверьте GitHub Actions для соответствующего SHA. Успешный деплой не доказывает прохождение тестов.

Не удаляйте записи или файлы данных вслепую: сначала определите источник и подтвердите тестовый характер затрагиваемых данных.
